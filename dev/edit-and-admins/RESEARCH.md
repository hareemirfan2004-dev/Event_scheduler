# Research: edit your name & trip details + group admins (scheduler)
> Changelog: v1 — 2026-07-22

## Verdict: GO
The feature is fully greenfield on the role side — grep confirms no isAdmin/role/owner concept anywhere; the only "creator" mentions are comments stating events don't record one. Every mechanism it needs already exists as prior art: `memberFromToken` returns the full Member row (an `isAdmin` column rides along with zero extra queries), the create-event validation block covers event edits, the join route's case-insensitive `name_taken` check is the rename template, and the `availability_free` migration proves hand-written backfill SQL in a migration file deploys safely via `prisma migrate deploy` on Vercel build. The required migration (additive column with default + one-shot UPDATE backfill) is strictly less risky than that already-shipped inversion migration. Out-of-window availability rows are provably inert in `lib/matching.ts`, so window edits need no data pruning.

## Current state
- **No roles.** Member is `id/groupId/name/token/createdAt` (`prisma/schema.prisma:26-37`). Privileges are flat family-trust: any member token creates events (`app/api/groups/[code]/events/route.ts:25`) and deletes any event (`app/api/events/[id]/route.ts:17-18`, rationale comment `:6-8`). The group creator is inserted alone as the first member at group creation (`app/api/groups/route.ts:22-31`), so **earliest `createdAt` per group = creator** — the backfill proxy. Reads order members `createdAt asc`.
- **Names.** `cleanName(value, 40)` (`lib/api-helpers.ts:24-29`) is the only sanitizer. Uniqueness is case-insensitive **in JS only** — `m.name.toLowerCase()===name.toLowerCase()` scan in `app/api/groups/[code]/join/route.ts:28-30`; the DB `@@unique([groupId,name])` (`schema.prisma:36`) is case-SENSITIVE. Clash → 409 with message literal `name_taken` (`join/route.ts:42`), matched client-side by string equality (`app/g/[code]/page.tsx:53`). `claimExisting:true` returns the SAME member row + token (identity restoration, `join/route.ts:32-40`; asserted `tests/api.test.ts:114-126`).
- **Event validation** (inline in create POST, `app/api/groups/[code]/events/route.ts:28-59`): title `cleanName(·,80)`; mode ∈ {DAY,SLOT}; `ISO_DATE` on both dates; `windowEnd < windowStart` → 400 (equal allowed); span ≤ 366 days; durationDays integer ≥1 ≤ windowDays (SLOT forces 1). Not extracted — no second caller until now.
- **Matching ignores out-of-window rows**: every read of the freeDates/freeSlots maps is keyed by an in-window day (`lib/matching.ts:66-75,105-114,130-138,158-161`), so rows outside `[windowStart,windowEnd]` are never queried. Shrinking a window is non-destructive; re-widening reactivates old marks.
- **Payloads/types.** Both GETs select members as `{id,name}` only (`app/api/groups/[code]/route.ts:16-19`, `app/api/events/[id]/route.ts:37-40`); client type `MemberInfo {id,name}` (`lib/client/types.ts:4-7`) feeds both `GroupPayload` and `EventPayload`.
- **Client stores.** `saath:<CODE>` identity `{memberId,memberName,memberToken}` (`lib/client/identity.ts:10-16`, `saveIdentity:39-43`); `saath:groups` hub store `SavedGroup{code,groupName,memberName,lastOpenedAt}` (`lib/client/groups.ts:4-11`). Both are written together on join (`app/g/[code]/page.tsx:40-50`, `components/landing-forms.tsx:33-42`). Note: the hub card does NOT currently display `memberName` (`components/my-groups.tsx:27-72`) — update the store anyway to keep it truthful.
- **UI patterns.** Member chips: `app/g/[code]/page.tsx:213-227` (self = `bg-leaf-wash` + "(you)"). Two-state name form with `name_taken` handling: `JoinGate` (`page.tsx:18-116`). Inline confirm panels: `DeleteEvent` (`app/g/[code]/e/[id]/page.tsx:13-75`) and hub `Remove` (`my-groups.tsx:42-69`). Form template for the edit-details form: `components/new-event-form.tsx` (raw `<input type="date">`/number inputs with inline Tailwind at `:90-134`, not TextInput). `api()` wrapper already supports arbitrary method+token (`lib/client/api.ts`).
- **Tests.** 9 vitest suites, 59 tests (run vs the Neon dev branch, ~80s). `tests/api.test.ts` drives handlers as plain functions: `jsonRequest`/`ctx` helpers (`:29-44`, ctx wraps params in `Promise.resolve` for Next 16), `beforeAll` raises all POLICIES to 10k (`:11-20`), `afterAll` deletes created groups + sweeps `:local` rate-limit rows (`:24-27`) — new tests must push ids to `createdGroupIds`.
- **Rate limiting** guards only the 4 anonymous scopes (`PolicyScope` closed union, `lib/rate-limit.ts:14`); token-authed mutations (event POST/DELETE, availability PUT) are deliberately unguarded — new PATCH routes follow that convention, no new scope.

## Constraints
- **Settled design decisions (brainstormed & approved with the user 2026-07-22 — the plan must respect these):** edit scope = title + dates + duration, mode immutable; admin model = creator is admin + admins promote/demote, backfill earliest member; event edit AND delete admin-only; event creation and availability stay any-member; rename = self only, no claim flow on clash, reuse `name_taken` copy pattern; server refuses demoting the last admin ("A group needs at least one admin"); 403 copy "Only a group admin can do that."; UI stays on existing pages (chips + event page), no new routes/pages; renames update both localStorage stores before reload.
- Prisma 7: config in `prisma.config.ts` (CLI doesn't auto-load .env); generator `prisma-client` → `lib/generated/prisma`; after schema change run `npx prisma generate` + delete `.next` before dev (recorded gotcha).
- `npm run build` = `prisma generate && prisma migrate deploy && next build` — dropping the migration folder is all deploy needs; additive-with-default = deploy-safe, no timing constraints.
- AGENTS.md mandate: read `node_modules/next/dist/docs/` before writing Next code (Next 16 async `ctx.params` pattern confirmed in every existing route).
- Case-insensitive name uniqueness has NO DB backing — rename must do the JS scan (excluding self) and tolerate the same tiny concurrent-join race join accepts (`join/route.ts:26-27` comment).
- Repo conventions: Conventional Commits with scopes; feature branches `feat/<slug>`; TDD (watch RED first); tests hit Neon dev (~80s, flaky — retry once); keep the api-suite `afterAll` sweeps intact.
- Known environment: port 3000 is held by a stale pre-existing `next dev` (PID 12724) — dev servers land on 3001.
